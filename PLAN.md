# Beli's SkyLyrics — work plan

Free, open-source (AGPL-3.0) Fabric mod for Minecraft 1.21.11: synced lyrics of whatever song
is playing on your PC, glowing in the sky. Linux first. Must work with Sodium, Iris and shaders.

Owner's request: free recreation of the paid "Neon Lyrics" mod, tasteful config GUI,
photos + videos, keep improving until it's perfect, then upload to GitHub (FOSS).

## Rules for whoever picks this up (incl. the cron loop)
- Record the PID when you start a background job (`cmd & echo $!`) and stop only that PID; never pkill, killall or pkill -f (2026-11-14 22:30 a name-matched kill took down every Gradle build on the PC, and `pkill -f` also matches its own shell).
- Build: `JAVA_HOME=/usr/lib/jvm/java-25-openjdk ./gradlew build` builds and tests every Minecraft version
  (Loom needs Java 25 to run; the 1.21.11 jar targets Java 21, the 26.x jars Java 25). `:26.2:build` builds one.
- Run the game with ONE version: `./gradlew :1.21.11:runProductionClient` (or `:26.1.2:`, `:26.2:`, `:26.3:`).
  A bare `runProductionClient` starts every version. 1.21.11 uses `run-prod/`, the others `run-prod-<version>/`.
- There is one source tree for all versions (Stonecutter); the old `mc-26.2` branch is retired, don't merge into it.
  Before a release, start each version once on the test screen to check it boots.
- Test in game WITHOUT stealing the owner's screen: run the game on a Hyprland headless
  output (`hyprctl output create headless SKYLYRICS`). Create it only while a test is running
  and `hyprctl output remove SKYLYRICS` at the end of EVERY test session (first move any
  non-test workspace back to DP-3); a leftover output makes the owner's PC think it has two screens.
  Never add a window rule matching `Minecraft.*`: it grabs the owner's own game if they start
  it mid-test. Move only the test client's window, by its PID, to the test workspace.
  Never test while the owner is playing (`pgrep -fa 'java.*minecraft'` shows their game), and
  check `hyprctl clients -j` again just before each batch of shots.
- Keep focus on the owner's screen. New windows open on the FOCUSED monitor (2026-11-14 a window opened
  for the owner landed on the hidden screen because SKYLYRICS had focus). Right after creating the output
  and after every window move, run `hyprctl eval 'hl.dispatch(hl.dsp.focus({ monitor = "DP-3" }))'`,
  and before each batch of shots confirm `hyprctl monitors -j` shows SKYLYRICS with "focused": false.
  Place SKYLYRICS so it shares no edge with DP-3 (e.g. position 10000x3000), or the owner's mouse can slide onto it.
- After moving the test window, check `hyprctl clients -j` that it really is on the skytest workspace (a move sent
  before the window is ready can silently fail; 2026-11-15 a test window sat on the owner's workspace 1). Creating
  the output can pull focus onto it a moment later: wait 1-2 s and check focus again before launching.
- Never remove the SKYLYRICS output while a test game is still running: its window falls onto the owner's screen
  with focus (happened 2026-11-14 23:21). Close the game first. A running test game's Gradle wrapper also holds the
  shared build lock, so keep sessions short.
- Demo screenshots/videos use the built-in DEMO song with original lyrics, never real lyrics.
- Never hard-code real lyrics. Lyrics come from LRCLIB at runtime.
- Keep the owner's main Prism instance ("donut") untouched until a release is ready.
- Update the checklist below after each work session, then commit and push to GitHub
  (github.com/arbelonson-source/belis-skylyrics) so the owner can see progress.
